# 常见误读与准确边界

创建时间：2026-09-16 22:05 UTC+8

最后更新时间：2026-09-16 22:05 UTC+8

[English](./MISINTERPRETATION_GUARD.md) · [简体中文](./MISINTERPRETATION_GUARD.zh-CN.md)

| 常见误读 | 准确边界 |
|---|---|
| “这是一个 AI 模型” | Full Spectrum 是开放研究与治理工程体系，不训练或提供一个通用大模型 |
| “这是 Agent 编排平台” | 各产品不规划和执行任意 Agent 任务 |
| “Engine 会控制 AI” | Engine 进行确定性治理判断，不执行现实业务动作 |
| “Observer 是 APM 或通用监控” | Observer 记录治理 Observation、Evidence、Audit/Replay 和复核边界 |
| “Knowledge Governance 是 RAG 后端” | 它治理精确知识身份、版本、来源和生命周期 |
| “Protocol 是通信协议” | Protocol 定义连接层之上的治理语义，不负责消息传输 |
| “系统会自动处罚或执行动作” | 现实动作仍由获得授权的外部行动者或业务系统承担 |
| “工业图证明已经有客户部署” | 除非提供明确证据，公开工业案例均为合成案例 |
| “架构图证明所有集成已经完成” | 架构图解释目标关系；固定运行和 Evidence 只证明其声明范围 |
| “研究文章就是规范” | 研究材料非规范，不能覆盖 Protocol、Schema、代码、测试和 Release |
| “悲悯协议已经被代码完整实现” | 它是概念和治理研究方向；每项工程机制必须单独举证 |
| “全息递归会产生更大权限” | 递归是解释模型；权限仍需要明确身份、范围和授权 |
| “更高观察路径更正确” | 公共理解路径是并行镜头，不是人员或真理等级 |

## 当前公共边界

- Full Spectrum 不是 AI 模型或自动代表项目发言的主体；
- 任何仓库都不会自动取得对外部人、组织或系统的治理权；
- 固定、合成或离线证据不证明一般兼容、真实网络或生产就绪；
- 证据不足时必须保留 `UNKNOWN` 与 `NOT_CONFIRMED`。
